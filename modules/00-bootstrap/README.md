# 00 — Bootstrap

**Thesis.** This repository is an *executable* reference. Every empirical claim
in a README is produced by a program in the repo and injected here mechanically;
none is hand-typed. This module proves the machinery works and establishes the
five-language build (Go, Rust, OCaml, Swift, Kotlin) so later modules can spend
their words on semantics, not scaffolding.

## The falsifiability contract

A README block wrapped in `<!-- BEGIN:kind name -->` / `<!-- END:kind name -->`
is regenerated by `make docs`, which runs the [`capture`](../../tools/capture)
tool. Three kinds exist: `output` (a command's stdout), `snippet` (a region of a
real source file), and `file` (a committed artifact such as benchmark results).
The `docs-fresh` CI job re-runs `make docs` and fails on any diff, so a stale
number cannot survive review. If a measurement contradicts a thesis, the rule is
to fix the thesis; a counter-intuitive result is the good content.

The same trivial computation is written once per language. Each binary prints
two facts. The source is extracted, not retyped:

<!-- BEGIN:snippet go-sum -->
```go
// Sum returns 1 + 2 + ... + n. The value is identical on every 64-bit target
// and in every language, which makes it a clean cross-toolchain fixture.
func Sum(n int) int {
	total := 0
	for i := 1; i <= n; i++ {
		total += i
	}
	return total
}

// WordSizeBytes is sizeof(int) on this target: 8 on any 64-bit platform,
// so it is stable across the author's arm64 and a CI amd64 runner.
func WordSizeBytes() int {
	var x int
	return int(unsafe.Sizeof(x))
}
```
<!-- END:snippet go-sum -->

Its output, captured live:

<!-- BEGIN:output go-demo -->
```text
$ go run ./cmd/demo
sum(1..1000000) = 500000500000
word size (bytes) = 8
```
<!-- END:output go-demo -->

<!-- BEGIN:output rust-demo -->
```text
$ cargo run --quiet --bin demo
sum(1..1000000) = 500000500000
word size (bytes) = 8
```
<!-- END:output rust-demo -->

<!-- BEGIN:output ocaml-demo -->
```text
$ dune exec bin/main.exe
sum(1..1000000) = 500000500000
word size (bytes) = 8
```
<!-- END:output ocaml-demo -->

Swift and Kotlin (built via SwiftPM and `kotlinc` behind
`scripts/run-{swift,kotlin}.sh`, which strip build logs so only program output
is captured):

<!-- BEGIN:output swift-demo -->
```text
sum(1..1000000) = 500000500000
word size (bytes) = 8
```
<!-- END:output swift-demo -->

<!-- BEGIN:output kotlin-demo -->
```text
sum(1..1000000) = 500000500000
word size (bytes) = 8
```
<!-- END:output kotlin-demo -->

All five are byte-identical. `sum(1..n)` equals `n(n+1)/2` in every language;
the word size is `8` on any 64-bit target, stable across the author's arm64 and
a CI amd64 runner. The representational route differs, and that is the first
divergence worth naming: Go/Rust/Swift `Int` is 64-bit, OCaml `int` is 63-bit
(one tag bit), and Kotlin/JVM `Int` is 32-bit (so its accumulator must be a
64-bit `Long`). Same value, five different integer models. Because these
outputs are architecture-independent, `docs-fresh` gates them.

## Portable vs. non-portable captures

Some captures are honestly machine-specific: assembly, escape-analysis dumps for
a target, `go version`, benchmark timings. Those are marked `"portable": false`;
`make docs` regenerates them locally and commits them, but `docs-fresh` skips
them (a CI amd64 runner would legitimately differ). This keeps the gate reliable
without pretending arm64 assembly is universal.

Non-portable example — the toolchain the driver reports:

<!-- BEGIN:output go-version -->
```text
$ go version
go version go1.26.5 darwin/arm64
```
<!-- END:output go-version -->

## The benchmark harness

Microbenchmarks lie; the harness defends against it. `scripts/go-bench.sh`
runs `go test -bench -benchmem -count=N` and pipes through `benchstat`, whose
`±` column is the confidence interval. Benchmarks run only under the manual
`bench` CI job (shared runners are too noisy), and their committed summaries are
injected as `file` blocks. Module 00's benchmark exists only to prove the path:

<!-- BEGIN:file go-bench -->
```text
goos: darwin
goarch: arm64
pkg: github.com/dannywillems/go-for-systems-engineers/modules/00-bootstrap/go
cpu: Apple M4 Pro
       │     go      │
       │   sec/op    │
Sum-14   229.6µ ± 0%

       │     go     │
       │    B/op    │
Sum-14   0.000 ± 0%

       │     go     │
       │ allocs/op  │
Sum-14   0.000 ± 0%
```
<!-- END:file go-bench -->

`0 allocs/op` is the point: a counting loop escapes nothing. Later modules use
this same harness for claims that actually matter.
